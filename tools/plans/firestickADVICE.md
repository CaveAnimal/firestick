# Advice for Developers: Finding Where to Start

To help developers efficiently find where to start in their task list, follow these steps:

## 1. Start at the Top of the Document
- Always begin reading from the very top of the task list file.
- Important context, such as task status symbols and overarching goals, is often defined early in the document.

## 2. Search for `- [ ]` Systematically
- Use a systematic approach to locate tasks marked as "Not Started" (`- [ ]`).
- Begin from the top and search sequentially through the document to avoid missing tasks embedded in earlier sections.

## 3. Understand the Document Structure
- Familiarize yourself with the layout of the task list. For example:
  - Metadata and summaries are often at the top.
  - Detailed tasks and subtasks may be nested within broader sections.
  - Look for headings like "Phase 1" or "Week 1" to identify where actionable tasks are described.

## 4. Check for Subtasks
- Tasks may be broken into subtasks, which are equally important.
- Pay attention to nested lists under main tasks.

## 5. Use Contextual Clues
- If the task list references specific phases, weeks, or focus areas, align your search with those sections.
- For example, if you're working on "Testing Framework Setup," look for tasks under that heading.

## 6. Avoid Assumptions
- Don't assume tasks are only in specific sections (e.g., "Today's Focus").
- Tasks can appear anywhere in the document, including earlier sections.

## 7. Leverage Search Tools
- Use search tools to locate specific markers like `- [ ]` or keywords related to your role (e.g., "frontend," "React UI").
- However, ensure you review the context around the search results.

## 8. Clarify Task Details
- Once you find a task, ensure you understand its objective, inputs, outputs, and dependencies before starting.
- Refer to related documents (e.g., PRD, examples) if needed.
